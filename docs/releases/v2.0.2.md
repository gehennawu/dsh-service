# v2.0.2（2026-09-29）

v2.0.2 修复 DSH 桌面端（及不同构建环境下）模型厂家图标全灭的问题：将模型触发钮与分组标题的定位全面迁移到官方稳定语义锚点，彻底解耦对上游 CSS Module 类名哈希的依赖。

## 新增 / 修复

- **修复 · 模型厂家图标定位解耦类名哈希（修复桌面端图标全灭）**：官方 ModelSelect 的 CSS Module 哈希类名随构建环境漂移（npm 发行包为 `_7KE1Ra_`，桌面端 0.2.0-rc.1 为 `u91W7W_`，桌面端 0.2.0-rc.2 为 `wq12jW_`），导致硬编码类名的绘制规则在桌面端全量失效。本版本将触发钮定位迁移至官方稳定锚点（`[data-slot="conversation.input.model"] button` 及 `button[aria-haspopup="menu"]`）并在运行时标记自有属性 `data-dshsvc-model-icon-trigger`，样式表只认自有属性；同时将官方默认图标的让位逻辑改为写入官方内置变量 `--dsh-composer-model-icon-display: none`。
- **修复 · 收紧触发钮兜底锚点**：真机实测同一个 composer 座内的「选择工作区」按钮同样携带 `aria-haspopup="menu"` 且在 DOM 顺序中排在模型钮之前，兜底锚点现限定必须命中模型文案（`/模型|Model/i`），避免将厂家图标错误绘制到工作区选择器上。
- **修复 · 模型弹窗分组标题精准限定菜单范围**：通过触发钮的 `aria-controls` 属性定位模型菜单根（MenuSurface），仅在该菜单容器内部匹配 `data-menu-group-heading`，彻底避免全局查询误伤插件管理页或输入触发器等同样使用官方 `MenuGroup` 原语的无关菜单。

## Added / Fixed

- **Fixed · Model provider icons decoupled from class-name hashes (fixing missing icons on Desktop)**: official ModelSelect CSS Module class hashes drift across builds (npm releases use `_7KE1Ra_`, while Desktop 0.2.0-rc.1 uses `u91W7W_` and 0.2.0-rc.2 uses `wq12jW_`), causing hardcoded selectors to fail on Desktop. The trigger button is now located via official stable anchors (`[data-slot="conversation.input.model"] button` and `button[aria-haspopup="menu"]`) and tagged with the plugin's own `data-dshsvc-model-icon-trigger` attribute so CSS rules rely solely on own attributes. Official default icons are dismissed cleanly via the official `--dsh-composer-model-icon-display: none` variable.
- **Fixed · Tightened trigger button fallback anchor**: the workspace selector button within the same composer seat also carries `aria-haspopup="menu"` and precedes the model button in DOM order; the fallback query now requires matching model label keywords (`/模型|Model/i`) to avoid misidentifying the workspace button.
- **Fixed · Model menu group headings scoped to menu root**: the menu root (MenuSurface) is now resolved via the trigger's `aria-controls` attribute, querying `data-menu-group-heading` exclusively within that container to prevent unintentionally decorating unrelated menus (such as the plugin manager or input triggers) that share the official `MenuGroup` primitive.
