# v2.0.0（2026-09-28）

v2.0.0 为 DSH 桌面端（Electron）补齐适配：识别桌面宿主后，重启与一键升级改走应用侧引导，不再让宿主进程退出被桌面壳判为崩溃；同时把 DSH 兼容声明扩展到 `0.2.0-rc.1`（已真机挂载运行）。主版本号进位对应新增的平台面（DSH Desktop），Web / Docker / 终端等既有平台的行为与文案逐字保持不变。

## 新增 / 修复

- **新增 · DSH 桌面端（Electron）适配**：宿主进程识别到运行在桌面应用内时——「重启」按钮、对话里的 `/restart` 与备份恢复后的重启**不再退出宿主进程**（桌面壳会把非 0 退出判为崩溃并弹出原生「启动失败」对话框，且不会自动重拉），改为提示「请在桌面端退出应用后重新打开」，界面也不再空等自动恢复；**一键升级在桌面端置灰**并指向桌面应用自带的插件管理页（桌面端命令行不能启动或改写该应用独占的 profile，升级端点直接短路，不产生任何子进程调用）；健康诊断的「运行环境」行显示「由桌面端托管（Electron）；重启由桌面应用负责」。桌面端默认可用，无需额外配置。README 平台支持表增列 DSH Desktop（Windows 已验证；macOS / Linux 未验证）。
- **兼容 · 支持声明扩展至 DSH 0.2.0-rc.1**：对 rc.2→0.2.0-rc.1 全部 261 个提交做了源码级与产物级审查，未发现新增破坏面——20 条既有接缝 17 条字节级相同，客户端插件加载门禁、界面槽位私有面、设置面、会话格式与持久化产物逐字节相同，48 项官方 CSS 类锚点与 24 项主题令牌零漂移，客户端静态服务目录仍 8 项、89 个槽位契约键无删除，官方无包移除；`engines.dsh` 上界更新为 `<0.2.0-rc.2`，并已在 DSH `0.2.0-rc.1` 真机挂载运行。旧版 DSH（`>=0.1.1-rc.2`）兼容保持不变。升级前请注意 DSH 会话数据不支持跨版本降级恢复。
- **修复 · 窄屏下会话头部模式芯片的可见性**：窄窗口（手机宽度）不再把模式芯片挤出可视区，320~375px 档标题按省略号收缩，390px 以上标题保持完整。
- **修复 · 窄容器下版本卡两行沿用共享列对齐**：延续上一版的四列网格，窄宽度下不再退回「每行各自排版」——版本号与「本次更新内容」入口左右缘重新对齐，空间不足时入口按钮整体折到下一行并保持右对齐。
- **文档 · README 补充官方插件管理页的安装方式**：安装章节给出图形界面步骤（插件页 → 添加插件 → 包名填 `@gehennawu/dsh-service` → 安装，安装源用默认的 npm 官方源）与安装后的生效说明（宿主半重启 DSH 进程、客户端半刷新页面即生效；桌面端由应用自身托管，请退出应用后重新打开），命令行安装表格保留为方式二。

## Added / Fixed

- **Added · DSH Desktop (Electron) support**: when the host process detects that it runs inside the desktop app — the Restart button, the `/restart` command, and the post-restore restart **no longer exit the host process** (the desktop shell treats a non-zero exit as a crash and shows a native "startup failed" dialog without relaunching automatically) and instead instruct the user to quit and reopen the app, with no more waiting for an automatic recovery; **one-click upgrade is disabled** and points at the desktop app's own plugin manager page (the desktop CLI cannot boot or mutate that app-exclusive profile, so the upgrade endpoint short-circuits without spawning any subprocess); the runtime-environment diagnostics row reports "managed by DSH Desktop (Electron); restarting is the app's job". It works out of the box, with no extra configuration. The README platform table now lists DSH Desktop (Windows verified; macOS / Linux unverified).
- **Compatibility · Declared support through DSH 0.2.0-rc.1**: a source-level and artifact-level review of the full rc.2→0.2.0-rc.1 window (261 commits) found no new breakage — 17 of 20 existing seams are byte-identical, the client plugin loading gate, the slot private surface, the settings surface, and the session format/persistence artifacts are byte-identical, 48 official CSS class anchors and 24 theme tokens show zero drift, the client static service catalogue still holds 8 entries with no slot contract key removed, and no official package was dropped; the `engines.dsh` upper bound is updated to `<0.2.0-rc.2`, and real-host mounting on DSH `0.2.0-rc.1` is operational. Older DSH releases (`>=0.1.1-rc.2`) remain supported. Note that DSH session data is not downgrade-restorable across versions.
- **Fixed · Mode chip visibility on narrow viewports**: narrow (phone-width) windows no longer push the mode chip out of view; titles shrink with an ellipsis at 320–375px and stay complete from 390px up.
- **Fixed · Version card keeps its shared-column alignment in narrow containers**: the four-column grid from the previous release no longer falls back to per-row layout when space is tight — version numbers and the release-notes toggle realign, and the toggle wraps to the next line while staying right-aligned when it does not fit.
- **Docs · README documents installing from the official plugin manager**: the installation chapter now gives the graphical steps (Plugins → Add plugin → package name `@gehennawu/dsh-service` → Install, with the default official npm registry) and explains when each half takes effect (the host half after a DSH process restart, the client half on a page refresh; on Desktop the app owns the process, so quit and reopen it), keeping the command-line table as option 2.
