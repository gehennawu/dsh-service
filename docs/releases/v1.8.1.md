# v1.8.1（2026-09-18）

v1.8.1 是**模型统计的容错修复**：此前只要历史会话里存在一个读取不了的旧版会话，整个「模型统计」就会刷新失败、其它正常会话的用量也一起统计不出来。本版让统计逐会话容错，失败的会话单独列出并可查看原因，其余会话照常统计与落盘。

感谢 [@LOEPUR](https://github.com/LOEPUR) 提交 [Issue #2](https://github.com/gehennawu/dsh-service/issues/2) 并提供完整的报错原文与复现路径——错误信息里连原始日志路径和转换器名称都给全了，定位因此快了很多。

## 新增 / 修复

- **修复 · 单个会话读不了不再拖垮整批模型统计**（[#2](https://github.com/gehennawu/dsh-service/issues/2)）：会话在打开、读取、格式迁移或统计折叠任一环节抛错时，跳过该会话继续统计其余会话；已成功读取的结果照常写入索引，不会因为一个坏会话而全部作废。
- **新增 · 部分成功的跳过清单**：统计页显示「全局会话统计（不受项目筛选影响）：成功统计 N 个会话，跳过 M 个会话」，可展开查看每个被跳过会话的会话 ID、错误类型与原因摘要；中英双语。全部会话都失败时也会显示该提示，不再只剩一句笼统的「无法读取模型使用统计」。
- **修复 · 失败会话保留上次统计并标明过期**：已经统计过的会话这次读不出来时，其历史用量保留并标注为过期（仍计入总量），不会出现「数字凭空变小」；首次就失败的会话不计入，并会在下次刷新自动重试。
- **修复 · 统计不再出现半更新状态**：刷新改为在索引副本上完成，确认写入磁盘成功后才发布缓存。此前若中途失败，内存里会留下「前半批已更新、磁盘未更新」的不一致状态。
- **安全 · 错误详情只保留必要信息**：跳过清单只记录会话 ID、错误类型与固定原因文案，不写入异常原文——异常文本可能包含消息内容、文件路径或凭据。错误详情按类型走词典，不直接回显原始报错。
- **兼容 · 旧数据与旧响应不受影响**：新增字段为纯追加，token 折算口径未变，索引版本未升，不会强制重建历史统计；手改或截断过的索引文件也不会让统计直接报错。

## 兼容性与升级提示

- 本版为纯修复，无新增开关、无需迁移；升级后直接生效。
- **触发说明**：导致会话读不出来的原因是该会话的 v0 载荷不符合 DSH 冻结的格式清单（`summary requires notice form`），原始日志文件保持完好、未被改坏。本版不会「修好」那个会话，但不再让它影响其它会话的统计——它会出现在跳过清单里，并在每次刷新时重试。
- 若希望彻底消除该提示：**删除**这个会话即可；仅归档无效（归档只记录 id，统计仍会读到它）。删除前建议先备份原始日志文件。
- 本版本通过 436 项自动化测试。

## Added / Fixed

- **Fixed · one unreadable session no longer breaks the whole model-usage refresh** ([#2](https://github.com/gehennawu/dsh-service/issues/2)): when a session fails at any stage — open, read, format migration, or usage folding — it is skipped and the remaining sessions are still indexed, so a single bad session can no longer void everyone else's statistics.
- **Added · a skipped-session list for partial success**: the statistics page now shows "Global session indexing (not affected by project filter): N sessions indexed successfully, M skipped", expandable into each skipped session's ID, error type, and a safe reason summary, in both Chinese and English. The notice also appears when every session fails, instead of only the generic "Could not read model usage".
- **Fixed · failed sessions keep their last statistics and are marked stale**: a session that was indexed before but cannot be read again keeps its historical usage and is flagged stale (still counted in totals), so numbers never silently shrink; a session that fails for the first time contributes nothing and is retried on the next refresh.
- **Fixed · refreshes are no longer left half-applied**: the refresh now works on a copy of the index and publishes the cache only after the write to disk succeeds. Previously a mid-way failure could leave memory updated for the first batch while the file on disk was not.
- **Security · error details are kept to the minimum**: the skip list stores only the session ID, error category, and fixed reason text — never the raw exception, which can contain message bodies, file paths, or credentials. Reasons are localized by category instead of echoing the original error.
- **Compatibility · existing data and older responses keep working**: the new fields are purely additive, token accounting is unchanged, the index version is not bumped, and no historical rebuild is forced; a hand-edited or truncated index file no longer makes usage fail outright.

## Compatibility and upgrade notes

- This is a maintenance release with no new switches and no migration; it takes effect right after upgrading.
- **About the trigger**: that session cannot be read because its v0 payload falls outside DSH's frozen format inventory (`summary requires notice form`), and the original log file remains intact and unmodified. This release does not "repair" that session, but it no longer lets it block the statistics of every other session — it appears in the skipped list and is retried on each refresh.
- To remove the notice entirely, **delete** that session; archiving alone does not help (archiving only records an id, so the index still reads it). Consider backing up the original log file first.
- This release passes 436 automated tests.
