# v2.0.10（2026-10-16）

## 新增 / 修复

- **DSH 兼容声明改为开区间 `>=0.1.1-rc.2`（无上界）**：`0.2.1-alpha.4` 起宿主改为「插件声明了 `engines.dsh` 就由它单独裁决」（不再看 `peerDependencies`），上界写死会让每个 DSH 新版都把插件整包挡掉——启动日志才会出现提示、界面无任何提示，且插件自身的一键升级会被同一门禁挡死而无法自救。改为开区间后，新版 DSH 上插件照常加载，个别新功能可能尚未适配但不阻断使用，也无需仅为挪动上界而单独发版。下界仍然生效（`0.1.1-rc.2` 以下拒绝）。
- **插件列表补齐图标与中英名称/描述**：新增插件图标（双层服务器轮廓、蓝色）与中英展示文案，插件列表不再显示默认齿轮与裸包名。
- **兼容声明防回归**：新增自动化守卫，断言声明始终是「单下界开区间」、下界仍拒绝更低版本、且 `package.json`/`package-lock.json`/中英 README 三处口径一致，防止重新写入上界或镜像漂移。

## npm 安装 / Install from npm

在 DSH 插件管理页输入：

```text
@gehennawu/dsh-service@2.0.10
```

或使用命令行（将 `web` 换成你的 Profile 名）：

```bash
dsh plugin --profile web add @gehennawu/dsh-service@2.0.10
```

精确版本号可避免 pnpm 发布观察期自动回退到旧版本；新发布版本仍可能包含尚未发现的问题。

## Added / Fixed

- **Open-ended DSH compatibility range `>=0.1.1-rc.2` (no upper bound)**: since `0.2.1-alpha.4` the host decides plugin compatibility from a declared `engines.dsh` alone (ignoring `peerDependencies`). A pinned ceiling makes every new DSH release block the whole plugin — visible only in startup logs, with no in-UI hint — and blocks the plugin's own one-click upgrade, leaving no self-recovery path. With an open range the plugin keeps loading on newer DSH releases; individual features may lag without breaking anything, and no release is needed merely to move the ceiling. The lower bound still applies (versions below `0.1.1-rc.2` are refused).
- **Plugin list icon and localized name/description**: adds a plugin icon (blue two-server silhouette) plus Chinese and English display copy, so the plugin list no longer shows a default gear and a bare package name.
- **Regression guard for the compatibility declaration**: new automated assertions require the declaration to stay a single open lower bound, keep refusing lower versions, and agree across `package.json`, `package-lock.json` and both READMEs — so a ceiling or a drifted mirror fails the suite.

Enter `@gehennawu/dsh-service@2.0.10` in DSH’s plugin manager, or run the command above with your Profile name. Pinning avoids automatic fallback during pnpm’s release cooldown; newly published versions may still contain undiscovered issues.

Automated Linux + Docker regressions (847 tests: 846 passing, 0 failing, 1 optional skip) plus isolated real-machine verification on DSH `0.2.1-alpha.4`: plugin install exits 0, `/healthz` returns 200, and RPC reports host `0.2.1-alpha.4`; plugin metadata resolves through the official `readPluginMeta` (the function the plugin list page actually calls) to bilingual title/description and an inline SVG icon.
