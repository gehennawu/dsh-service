# v1.9.9（2026-09-24）

v1.9.9 扩展 DSH 兼容声明至 `0.1.7-rc.2`（真机挂载运行），并在备份归档与恢复预检中展示备份时的 DSH 版本，以及优化版本卡两行在宽窄屏下的列对齐表现。

## 新增 / 修复

- **兼容 · 支持声明扩展至 DSH 0.1.7-rc.2**：rc.2 源码级与产物级对照（rc.1→rc.2 全部 346 个提交、接缝文件及 CSS 哈希词干逐项审查）未发现新增破坏面，47 项选择器词干经产物 grep 定案零漂移；`engines.dsh` 上界更新为 `<0.1.7-rc.3`；当前已在 DSH `0.1.7-rc.2` 真机挂载运行。rc.1 起新增的插件版本兼容门禁只读取 `peerDependencies`，本插件无该声明，不受门禁约束。旧版 DSH（`>=0.1.1-rc.2`）兼容保持不变。升级前请注意 DSH 会话数据不支持跨版本降级恢复。
- **新增 · 备份归档记录创建时的 DSH 版本并在面板与预检中展示**：创建备份时文件名自动追加当前运行的 DSH 版本段（`dsh-backup-YYYYMMDD-HHmmss-dsh<version>.tar.gz`），归档内落地 `meta/backup.json`；面板列表行与恢复预检计划均直观展示快照出处版本，便于识别跨格式版本备份；导入同时兼容带与不带版本段的文件名。
- **修复 · 版本卡两行按共享列对齐版本号与更新内容入口**：版本卡内 dsh-service 与 DSH 两行采用共享四列网格，版本号靠右对齐并将两行间距固定，彻底解决因插件与宿主标签名长短不一导致「本次更新内容」入口错位的问题；窄容器与移动端（≤480px）平滑回退至行内连排与换行。

## Added / Fixed

- **Compatibility · Declared support through DSH 0.1.7-rc.2**: a source-level and artifact-level review of the full rc.1→rc.2 window (346 commits, seam files, and CSS class-name stems) found no new breakage, with 47 selector stems confirmed zero-drift via artifact grep; `engines.dsh` upper bound is updated to `<0.1.7-rc.3`; real-host mounting on DSH `0.1.7-rc.2` is operational. The plugin compatibility gate reads only `peerDependencies`, which this plugin does not declare. Older DSH releases (`>=0.1.1-rc.2`) remain supported. DSH session data is not downgrade-restorable across versions.
- **Added · Record and display backup-time DSH version in archives and restore preflight**: created backup archives now carry the running DSH version in their filename (`dsh-backup-YYYYMMDD-HHmmss-dsh<version>.tar.gz`) and store authoritative metadata in `meta/backup.json`; the backup list row and restore preflight plan display the originating version to prevent unintended downgrade restores; archive import accepts both versioned and legacy filenames.
- **Fixed · Version card shared-column alignment for version numbers and release notes entries**: the dsh-service and DSH rows now share a four-column grid layout with right-aligned version numbers, eliminating horizontal misalignment of the "release notes" toggle caused by differing label lengths; narrow containers and mobile viewports (<=480px) smoothly fall back to inline wrapping.
