# v2.0.3（2026-09-29）

v2.0.3 完善模型厂家图标定位机制：收紧触发钮兜底锚点，避免将厂家图标错误绘制到同一 composer 座内的「选择工作区」按钮上。

## 新增 / 修复

- **修复 · 收紧触发钮兜底锚点（避免误伤工作区选择器）**：真机实测同一个 composer 座内的「选择工作区」按钮同样携带 `aria-haspopup="menu"`，且在 DOM 顺序中排在模型选择钮之前。盲取第一个会导致厂家图标被错误挂载到工作区选择器上。本版本将兜底锚点收紧为必须命中模型文案关键词（`/模型|Model/i`），确保仅定位到真正的模型选择钮。
- **修复 · 模型厂家图标定位解耦类名哈希**：官方 ModelSelect 的 CSS Module 哈希类名随构建环境漂移（npm 发行包为 `_7KE1Ra_`，桌面端 0.2.0-rc.1 为 `u91W7W_`，桌面端 0.2.0-rc.2 为 `wq12jW_`）。本系列版本将触发钮定位迁移至官方稳定锚点（`[data-slot="conversation.input.model"] button` 及命中模型文案的 `button[aria-haspopup="menu"]`），样式表只认自有属性 `data-dshsvc-model-icon-trigger`；同时通过触发钮的 `aria-controls` 精准限定模型菜单根，避免弹窗分组图标误伤其它菜单。

## Added / Fixed

- **Fixed · Tightened trigger button fallback anchor**: the workspace selector button within the same composer seat also carries `aria-haspopup="menu"` and precedes the model button in DOM order; blind selection caused the provider icon to be drawn onto the workspace selector. The fallback query now strictly requires matching model label keywords (`/模型|Model/i`) to ensure only the model button is targeted.
- **Fixed · Model provider icons decoupled from class-name hashes**: official ModelSelect CSS Module class hashes drift across builds (npm releases use `_7KE1Ra_`, while Desktop 0.2.0-rc.1 uses `u91W7W_` and 0.2.0-rc.2 uses `wq12jW_`). Trigger buttons are located via official stable anchors (`[data-slot="conversation.input.model"] button` and model-labeled `button[aria-haspopup="menu"]`) tagged with `data-dshsvc-model-icon-trigger` so CSS rules rely solely on own attributes, with menu group headings strictly scoped to the menu root.
